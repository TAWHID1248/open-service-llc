# OPEN SERVICE LLC - Deployment Guide

This guide covers deploying the OPEN SERVICE LLC website with:
- **Backend (Django REST API)** → Railway
- **Frontend (React + Vite)** → Vercel

---

## Prerequisites

1. GitHub account with the repo pushed: https://github.com/TAWHID1248/open-service-llc
2. Railway account: https://railway.app (free tier available)
3. Vercel account: https://vercel.com (free tier available)

---

## Part 1: Backend Deployment (Railway)

### Step 1: Connect Railway to GitHub

1. Go to https://railway.app and sign up/log in
2. Click **"New Project"** → **"Deploy from GitHub repo"**
3. Connect your GitHub account and select the `open-service-llc` repo
4. Select the `backend` directory as the root directory
5. Click **"Deploy"**

### Step 2: Configure Environment Variables

Once deployed, go to your Railway project settings and add these environment variables:

```
SECRET_KEY=generate-a-secure-key-here
DEBUG=False
ALLOWED_HOSTS=your-railway-app.up.railway.app,localhost
DATABASE_URL=postgresql://user:pass@host/dbname  (auto-generated by Railway)
CORS_ALLOWED_ORIGINS=https://your-vercel-app.vercel.app
```

**Note:** Railway automatically provides a PostgreSQL database. Use `${{DATABASE_URL}}` to reference it.

### Step 3: Run Migrations

In your Railway project dashboard:
1. Go to **"Settings"** → **"Deploy Logs"** or **"CLI"**
2. Railway will automatically run the `release` command in Procfile:
   - `python manage.py migrate`
   - `python manage.py seed_data`

Your backend is now live! Note the URL (e.g., `https://backend-production.up.railway.app`)

## Part 2: Frontend Deployment (Vercel)

### Step 1: Connect Vercel to GitHub

1. Go to https://vercel.com and sign up/log in with GitHub
2. Click **"New Project"** → **"Import Git Repository"**
3. Select the `open-service-llc` repo
4. Under **"Framework Preset"** select **"Vite"**
5. In **"Root Directory"**, set it to `frontend`
6. Click **"Deploy"**

### Step 2: Configure Environment Variables

Before deployment (or in project settings after):

1. In Vercel project → **"Settings"** → **"Environment Variables"**
2. Add the variable:
   ```
   VITE_API_URL=https://your-railway-backend-url.up.railway.app/api
   ```
   Replace with your actual Railway backend URL.

### Step 3: Redeploy Frontend

1. After adding the env var, go to **"Deployments"**
2. Click the three dots on the latest deployment → **"Redeploy"**
3. Wait for deployment to finish

Your frontend is now live! The URL will be something like `https://open-service-llc.vercel.app`

---

## Part 3: Update CORS & Django Settings

After both are deployed:

1. In Railway dashboard, update `CORS_ALLOWED_ORIGINS` to include your Vercel URL:
   ```
   https://your-vercel-app.vercel.app
   ```

2. Update `ALLOWED_HOSTS` to include your Railway URL:
   ```
   your-railway-app.up.railway.app
   ```

3. Railway will auto-redeploy when env vars change.

## Testing the Deployment

1. Open your Vercel frontend URL in a browser
2. Navigate through pages (Home, Services, About, Contact, etc.)
3. Open browser DevTools → **Console** and check for errors
4. Test the Contact form - should submit to Railway backend
5. Check that testimonials, FAQs, and services load from the API

## Troubleshooting

### CORS Errors
If you see `CORS error` in console:
- Verify `CORS_ALLOWED_ORIGINS` includes your Vercel URL
- Check that the backend `VITE_API_URL` env var is correct in Vercel
- Redeploy both services after changes

### 404 on API Calls
- Verify the `VITE_API_URL` includes `/api` at the end
- Check Railway backend is running (check Logs in Railway dashboard)
- Confirm database is initialized (`python manage.py seed_data`)

### Static Files Not Loading
- Railway/Vercel handle static files differently
- Vite automatically bundles everything into `dist/`
- Vercel serves the built `dist/` folder automatically

### Environment Variables Not Working
- Wait 5-10 minutes after adding env vars for Railway to redeploy
- Manually trigger redeploy in Vercel if needed
- Clear browser cache (Cmd/Ctrl + Shift + Delete)

## Local Development (if needed)

To run locally after setting up:

```bash
# Backend
cd backend
python -m venv venv
source venv/bin/activate  # or: venv\Scripts\activate on Windows
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_data
python manage.py runserver 8000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev
# Visit http://localhost:5173
```
